# Resulticks (RESUL)

> Resulticks is an enterprise omnichannel marketing automation and audience
> engagement platform, operating under the RESUL brand. It combines a
> cookie-independent customer data platform with campaign orchestration across
> email, SMS, WhatsApp, RCS, LINE, web push, mobile push, in-app, voice, social
> and paid channels, plus audience scoring, journey analytics and AI-assisted
> audience building. Resulticks publishes a public documentation portal with a
> REST API reference and mobile/web SDK guides, but ships no machine-readable
> API definition (no OpenAPI, AsyncAPI, GraphQL schema, or MCP server) and no
> public pricing. The API base domain is https://apis.resu.io, which is not
> reachable from the public internet — access is customer-scoped.

This file was generated by API Evangelist from Resulticks' own public
documentation on 2026-08-13. Resulticks does not publish an llms.txt of its own
(/llms.txt returns 404 on resulticks.com and a soft-404 HTML shell on the docs
host).

## API

- [Resul Web API](https://gud.resulticks.com/API-reference/introduction/): REST
  API for account setup, data ingestion, audience list management,
  communication creation and scheduling, and response analytics. Base domain
  https://apis.resu.io. JSON request and response bodies; GET/POST/PUT/DELETE.
- [Web API controllers](https://gud.resulticks.com/API-reference/API-management/web-API-controllers/):
  the base domain, routing model, and the six documented API call categories —
  API Keys, Account Setup, Data Ingestion, Communication, Communication
  response analytics, and Statistical sharing.
- [API keys](https://gud.resulticks.com/API-reference/API-management/API-keys/):
  GET https://apis.resu.io/Apirsltks/Credentials with Username and Password
  returns an apiKey; 401 on rejection.
- [API gateway](https://gud.resulticks.com/API-reference/API-management/API-gateway/):
  hybrid multi-cloud gateway, OAuth for third-party REST authentication, SOAP
  access to the data model, and throttling at account/application/API/user
  level.
- [Manage role](https://gud.resulticks.com/API-reference/manage-role/) /
  [Manage permission](https://gud.resulticks.com/API-reference/manage-permission/):
  the RBAC surface over Resul objects.

## API reference modules

- [Account setup](https://gud.resulticks.com/API-reference/modules/account-setup/account-setup-signup/):
  signup, profile, health check, and per-channel communication settings (email,
  SMS, mobile push, web push, alerts and notifications, frequency setup).
- [Audience](https://gud.resulticks.com/API-reference/modules/audience/target-list/):
  target lists, dynamic lists, data attributes, dedup, CSV ingestion, and RDSM
  / SFTP metadata.
- [Communication](https://gud.resulticks.com/API-reference/modules/communication/communication-types/):
  communication types, email, SMS, mobile push, web push, offline conversion,
  and pre-communication summary.
- [Analytics](https://gud.resulticks.com/API-reference/modules/analytics/analytics-list/):
  Audience 360 (overview, behaviour, timeline, top channel, repeat visitors),
  channel key metrics, blast and delivery counts, performance and summary
  reports, benchmarks, insights, and PDF report export.

## Known gaps

- No OpenAPI, AsyncAPI, GraphQL SDL, or Protobuf definition.
- No MCP server and no A2A agent card.
- No /.well-known/ documents on any host; no security.txt.
- No changelog, status page, versioning policy, deprecation policy, or SLA.
- No published rate-limit numbers or rate-limit response headers.
- No public pricing — enterprise contact-sales only.
- No idempotency contract; success and failure share HTTP 200 with an
  IsError body flag.
